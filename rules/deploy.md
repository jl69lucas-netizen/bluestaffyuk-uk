# Where work lands and how it ships

Rules moved out of `CLAUDE.md` on 2026-08-02 (Phase 4), re-based for BlueStaffyUK
2026-09-16. **This pack is the one that was rewritten rather than re-worded**: BSUK has no
remote, nothing deploys until project 6, and a rule that says "push after every build"
would be an instruction to do something impossible.

`enforced:` says what actually holds the rule up.
`test` — a committed check fails when the rule is broken. `judgment` — no mechanical
decision procedure exists, and `data/quality/rule-index.json` records why.
`untested` — **a deletion candidate**: it is asserted and nothing enforces it.
`scripts/quality_report.py` §5 lists every one of those on every run, which is the point.


---
id: src-pages-is-deployed
enforced: untested
family: GATE
---

- **`src/pages` is the built source** — All page edits MUST go to `src/pages/<slug>/index.astro`
  (or `index.html`). `dist/` is Astro's **output**: it is regenerated by `npm run build`, every
  gate reads it, and an edit made there is erased by the next build while the gates go on
  reporting it as shipped. If a page appears to need a `dist/` edit, the change belongs in
  `src/pages/` or in a component under `src/components/`.

---
id: work-on-foundation-not-main
enforced: judgment
family: GATE
---

- **Work on `foundation`, commit, and NEVER push until project 6 (ALWAYS) — applies to every
  agent, skill, and build** — BSUK's trunk is `foundation`; project work is cut from it onto a
  named branch (`system-transfer` is this project's) and merged back when its gates pass.
  **The repo has no git remote and must not be given one.** Do not run `git remote add`, do not
  run `git push`, and do not open a PR — there is nothing on the other end, and adding one
  early publishes a site whose prices, phone number and licence claims are still placeholders
  (`PHONE_PLACEHOLDER`, `SITE_URL_PLACEHOLDER`, `LICENCE_CLAIM_PLACEHOLDER`,
  `LEGAL_CLAIM_PLACEHOLDER`). Publication is **project 6's** job and nobody else's. `scripts/placeholder_check.py` is what stands between a placeholder and a
  live page; it exits non-zero while any placeholder remains, and that non-zero is correct.

---
id: commit-after-build-never-push
enforced: judgment
family: GATE
---

- **Commit after every build — and NEVER push (ALWAYS) — applies to every agent, skill, and
  build** — The half of CAG's rule that survives is the first half: after any agent or skill
  completes a build or an edit, **commit immediately**. Finished work left uncommitted is the
  failure mode this rule exists for, and it is the only one of the two that BSUK can still
  suffer. The second half — `git push` — is **deleted, not deferred**: on CAG push meant
  deploy, and here there is nothing to push to and nothing that should go live. Every commit
  carries the project trailer. Do not stage `.env`; check `git status` first.

---
id: release-guarded-publication
enforced: untested
family: GATE
---

- **Push, IndexNow and pagefind are INACTIVE until project 6, guarded by `BSUK_RELEASE=1`
  (ALWAYS)** — Three shipping steps exist in the toolchain and none of them may run in
  projects 1–5: the **push/deploy** step, the **IndexNow submit** step, and the **pagefind
  index build**. Each is written so it refuses to act unless `BSUK_RELEASE=1` is set in the
  environment, and the variable is set by a human at release time, never by a script, a
  hook, an agent, or a test. The reasons are specific: a deploy publishes placeholder
  content; an IndexNow submit asks Bing to crawl URLs that resolve to nothing, under a key
  that does not exist yet; and a pagefind index built over placeholder pages ships a search
  box that answers questions wrongly. Running any of them "just to check it works" is not a
  check — it is the publication. If you need to prove the wiring, run the step's own dry-run
  path, read its output, and leave `BSUK_RELEASE` unset.

---
id: no-credential-in-a-committed-file
enforced: untested
family: GATE
---

- **No credential value in any committed file, report, Artifact, or on stdout (ALWAYS)** —
  Every key BSUK uses (`GSC_*`, `GA4_*`, `PUBLIC_FORMSPREE_ID`) lives in the gitignored
  `.env`; `.env.example` lists the key names with empty values, and
  `docs/reference/credentials.md` says which script reads which key. Scripts read from the
  environment and never print what they read. A value pasted into a commit message, a gate
  report, a published Artifact, or a terminal transcript is disclosed whether or not the file
  is later edited — the git history keeps it. Check `git status` before every commit.
