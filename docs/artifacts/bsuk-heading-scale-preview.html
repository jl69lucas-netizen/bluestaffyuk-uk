What is wrong

On all twelve built pages, 49 H2s and 217 H3s paint at 17px, the same size as the body text, at 375, 768 and 1280 alike. Most are also at weight 400, so the only thing that marks them as headings is the Fraunces face. A reader scanning the health page cannot tell "Our Rigorous Health Testing Process : Ensuring Peace of Mind" from the paragraph under it.

The cause is one missing rule. The only heading size set for body sections is .bl-box h2 { font-size: var(--text-2xl) } in src/styles/board-styles.css. Every other H2 and H3 (the migrated sections outside a .bl-box, and the H3s inside a box's body) inherits the body size from the Tailwind preflight.

Why nothing caught it

No check was silent, because no check covers it. layout-min-font-size is a floor for all text, and 17px passes it. sem-heading-order reads heading levels, not sizes. city-type-fit caps heading sizes from above, only on city routes, and sets no floor. The missing invariant is simple: a body H2 or H3 must paint larger than the body text. Source: Known Issue 97, measured in Chromium on dist/ (BSUK-refs/london/_plan2-shots/close/heading-sizes.json).

Three options

One scale for body H2, H3 and H4 inside <main>, taken from the London city scale in src/styles/city.css so city pages and the built pages share one rhythm. The tiers are the city kit's own edges: phone below 640px, tablet 640–799px, desktop 800px and up. Body text on these pages is 17px at every width.

All three share the same spacing and wrapping, so only the sizes differ:

  • H2 margin: 32px above and 8px below on phone, 40 / 12 on tablet, 48 / 12 on desktop (--space-6 to --space-8).
  • H3 margin: 24px above and 8px below on phone and tablet, 32 / 8 on desktop.
  • H4 margin: 24 / 4.
  • First child: a heading that opens its section takes no top margin.
  • Wrapping: text-wrap: balance on all three levels, with no ch measure cap.
  • Unchanged: Fraunces and Source Sans 3, the colours (headings keep --color-ink) and every token.

Why (a) is the recommendation

The city type scale is already built, gated and approved (city.css, gated by tests/render/lib/cityTypeFit.ts, from your ruling of 2026-09-28), so applying it here means one rhythm across the site rather than a second scale.

(a) makes one deliberate change to the city scale. The city H3 is 17px on phone because city body text there is 16px. These pages set body text at 17px, so a 17px H3 would still equal the body and fail the new check. The phone H3 is therefore 18px at weight 600.

(a) also leaves out the city's H2 measure (22 / 28 / 34ch). The city needs it for its narrow 656px sections. On these full reading columns it pushed three more headings to four lines, which the run below measured.

Trade-off: at 375px, eight long migrated headings wrap to four or five lines. As built, four of them already do. (b) gives the same count, and (c) gives ten.

The CSS for each option

Each block is scoped the way the real fix would be. It is in @layer components, so a caller's utility class still wins. It selects body headings in <main> only, so the site header and footer are untouched. A .bl-box's own H2 keeps --text-2xl, and it skips anything inside a kit-* or city-kit component, whose scoped styles win anyway. Every selector sits inside :where(), so its specificity is (0,0,1) and .bl-stub h3 and the kit rules still beat it.

(a) City scale — Recommended

@layer components {
  /* Body headings in <main>. Not a .bl-box's own H2 (it keeps --text-2xl), not a kit or city-kit component. */
  main :where(h2:not(.bl-box h2, [class*="kit-"] *, .city-kit *)) { font-weight: 700; line-height: 1.18; text-wrap: balance; }
  main :where(h3:not([class*="kit-"] *, .city-kit *)) { font-weight: 600; line-height: 1.25; text-wrap: balance; }
  main :where(h4:not([class*="kit-"] *, .city-kit *)) { font-weight: 700; line-height: 1.3; text-wrap: balance; margin-block: var(--space-5) var(--space-1); }
  /* phone, below 640px */
  main :where(h2:not(.bl-box h2, [class*="kit-"] *, .city-kit *)) { font-size: 22px; margin-block: var(--space-6) var(--space-2); }
  main :where(h3:not([class*="kit-"] *, .city-kit *)) { font-size: 18px; margin-block: var(--space-5) var(--space-2); }
  main :where(h4:not([class*="kit-"] *, .city-kit *)) { font-size: 17px; }
  @media (min-width: 640px) { /* tablet */
    main :where(h2:not(.bl-box h2, [class*="kit-"] *, .city-kit *)) { font-size: 25px; margin-block: var(--space-7) var(--space-3); }
    main :where(h3:not([class*="kit-"] *, .city-kit *)) { font-size: 18px; margin-block: var(--space-5) var(--space-2); }
    main :where(h4:not([class*="kit-"] *, .city-kit *)) { font-size: 17px; }
  }
  @media (min-width: 800px) { /* desktop */
    main :where(h2:not(.bl-box h2, [class*="kit-"] *, .city-kit *)) { font-size: 28px; margin-block: var(--space-8) var(--space-3); }
    main :where(h3:not([class*="kit-"] *, .city-kit *)) { font-size: 20px; margin-block: var(--space-6) var(--space-2); }
    main :where(h4:not([class*="kit-"] *, .city-kit *)) { font-size: 18px; }

What applying it would change

If you pick an option, the fix follows the learning loop: the check first, then the style.

  • The check, first. Add layout-body-heading-above-body to tests/render/checks/layout.ts. At 375, 768 and 1280 it fails when a visible H2 or H3 in <main>, not inside a kit component, paints at or below the page's body size. The body size is the font-size carrying the most paragraph text. It records how many headings it examined, so zero examined is a failure.
  • Its fixture. Add tests/render/fixtures/known_broken/layout-body-heading-above-body.html: an unboxed <h2> and <h3> at the inherited 17px over 17px prose. Watch npm run test:render:meta fail on it before the check exists, then pass once it does.
  • The style. Add the chosen block to src/styles/board-styles.css, beside .bl-box h2, inside its existing @layer components. global.css imports that file, so it reaches all twelve built pages. It adds one block and edits no existing selector.
  • Then: npm run build, npm run test:render:pages at 375 / 768 / 1280, and npm run check:all. Known Issue 97 closes with the before and after counts.
  • Not in this change: rewording the eight long headings (content, and mostly the verbatim set) and heading colour. rules/design.md gives headings --color-brand, and the city kit already uses it, but the built pages paint them in --color-ink. That would be its own preview.

Noticed while measuring, not fixed

  • No phone gutter on unboxed prose. At 375 the unboxed sections' paragraphs and headings run from x = 0 to 375 on the health page, the buying guide and the privacy policy. They have no side gutter, which shows in every 375 shot above. It is a separate defect for its own Known Issue.
  • Boxed H2s are tall on phone. A .bl-box H2 is 30px (--text-2xl) at 375, with the inherited 1.65 line-height. The health page's first boxed H2 is four lines, 198px tall. This preview leaves .bl-box alone, as asked, but that rule sits outside the city caps too.
