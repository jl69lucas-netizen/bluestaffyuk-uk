Watch every background agent, two ways

Both designs are drawn the way the mod actually renders in the side pane: real text on dark steel cards, with no picture to shrink. The sample data is this session's real agents. Each agent's work type comes from the tools it is calling: Research for web fetches and searches, Reading for opening files, Writing for editing files, Testing for build, test and gate runs, and Committing for git. Pick one; the status line ships with either.

A · Agent Cards

Recommended

One card per agent, running agents first. Each card shows the job, the agent type and model, how long it has run, the number of tool calls, what it is doing now (with the exact last command), and a strip of its last 20 actions in work-type colours. The top card is the fleet: running, done and failed counts, plus one bar showing what the whole fleet is spending its effort on.

B · Agent Timeline

Gantt ribbons

One lane per agent on a shared clock. Each lane is a ribbon coloured by what the agent was doing minute by minute, so you see when it started, how long it ran, and where its time went: research early, then writing, then testing. Finished lanes end in a ✓. It is better for "where did the time go" than "what is it doing now".

My recommendation: A · Agent Cards

The side pane is tall and narrow (your screenshots), so cards stack down its full length and stay readable with 11 agents. The question you asked, "what type of work is each doing", is answered on every card in words and colour. B's timeline needs width to be useful: in a narrow pane its ribbons get thin and the clock labels collide, so it pays off only when the pane is expanded. Trade-off: A shows less history at a glance than B; the 20-action strip is A's compact version of it.

The mod reads only what the engine reports. It never reads an agent's transcript, never sends anything anywhere, and keeps no key. Agents launched before the mod loads appear from the live list without their earlier tool history.
