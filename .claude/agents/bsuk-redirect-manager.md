## The rule file

`data/redirects.json` is the only file you edit:

```json
{ "from": "/<old-slug>/", "to": "/<new-slug>/", "type": 301, "reason": "page renamed 2026-09-23" }
```

`npm run redirects` (`scripts/build_redirects.py`) regenerates `public/_redirects` from it, rule for rule and in order; the first matching rule wins, a trailing `*` is a prefix splat and `/:name/` matches one path segment. Never hand-edit `public/_redirects` — its first line says so. There is no www rule: host-level redirects are project 6's, when a host exists.

## Protocol A — Add New Redirects

1. **The target is served** — `npm run build`, then `ls dist/<new-slug>/index.html`. Never add a redirect to a page that does not exist; build it first.
2. **The source has no rule yet** — `grep '"/<old-slug>/"' data/redirects.json`. If it has one, you are flattening a chain (Protocol B).
3. **Add the rule** to `data/redirects.json` with a `reason` that says what moved and when.
4. **Regenerate and gate** — `npm run redirects && npm run build && npm run check:redirects`; read the examined count and every problem line.

## Protocol B — Chains

`npm run check:redirects` reports every chain (`/<a>/ → /<b>/ → /<c>/`). Flatten it in `data/redirects.json`: point `/<a>/`'s `to` at `/<c>/`, keep `/<b>/ → /<c>/`, regenerate, re-run the gate.

## Protocol C — Targets

`npm run check:redirects` checks that every `to` — wildcard rules included — exists under `dist/`. A missing target is fixed by building the page or re-pointing the rule, and the `reason` says which.

## Protocol D — Full Audit

Run Protocol A's step 4 and report:

```markdown
# Redirect Audit — [date]
Rules in data/redirects.json: [X]
Gate: [the last line of npm run check:redirects]

## Chains
| From | Via | To | Fix |
|------|-----|----|-----|

## Missing targets
| From | To | Fix |
|------|----|-----|
```

## Rules

1. **Edit `data/redirects.json` only** — `public/_redirects` is generated by `npm run redirects`
2. **Always add both slash variants** — `/<slug>` AND `/<slug>/` for every new rule
3. **Validate target before adding** — no redirect to a missing page
4. **301 for permanent, 302 for temporary** — default to 301 unless explicitly told otherwise
5. **Flatten all chains** — A→B→C must become A→C; B→C stays
6. **Give every rule a `reason`** — what moved and when
7. **Never redirect to external domains** — outbound redirects are not managed here
